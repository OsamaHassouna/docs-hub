This playbook is published as an [MCP server](https://modelcontextprotocol.io/) + terminal CLI so AI clients and dev workflows can pull rules and components into whatever they're building. The model (or you) calls structured tools, you stay out of copy-paste hell, and the same rules ship to every surface.

**Safe by design:**

- One dependency — the official MCP SDK, nothing else
- No postinstall scripts
- Read-only tools — it never reads or sends mail, and never touches your inbox
- The local stdio server reads a bundled spec; it makes no outbound network calls

## See it work in 10 seconds — no install

One curl against the hosted endpoint returns a real, production-ready pattern. This pulls the bulletproof Outlook button straight from the playbook:

```bash
curl -s https://docs.osamahassouna.com/api/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get_component","arguments":{"name":"buttons"}}}' \
  | jq -r '.result.content[0].text | fromjson | .html'
```

Returns the actual VML-wrapped button this site documents — the `<v:roundrect>` Outlook fallback behind a styled `<a>`:

## What it gives the model

Five tools. All read-only, all deterministic, all serving the same content you read on this site.

| Tool | What it returns |
|---|---|
| `list_categories` | The four rule categories (structure, compatibility, production, ai-generation) with page counts and the slug and title of every page. |
| `get_playbook_rules` | The rule pages for a category. `format: "full"` (default): title, description, checklist, body, all code examples. `format: "checklist"`: each page's title, description and the rules to follow, a few KB per category; leave out `category` to get every page in one call (about 16 KB). |
| `get_rule` | One rule page by slug (`compatibility/responsive`, or just `responsive`): title, description, checklist, and the body with its code. Add `include_examples: true` for the code as a separate array. |
| `list_components` | All six components (buttons, spacing, images, inline-icon, background-images, text) with metadata: subcategory, VML flag, responsive flag. |
| `get_component` | Full record for one component — title, description, narrative, HTML pattern, slots, examples. |

The model uses these to discover and quote the exact playbook patterns instead of hallucinating its own table layout from training data. To keep the context small, it can read the checklists first and then pull only the pages it needs with `get_rule`. Components live in their own dimension — use `list_components` / `get_component`, not `get_playbook_rules`.

## CLI

The same package ships a terminal command for direct use:

```bash
email-playbook --help

email-playbook list-categories
email-playbook get-rules structure
email-playbook get-rules structure --checklist
email-playbook get-rule responsive
email-playbook list-components
email-playbook get-component buttons
```

The MCP tool names work as command names too (`list_categories`, `get_playbook_rules`, `get_rule`, `list_components`, `get_component`); arguments are positional, as above. `get-rules --checklist` with no category prints every page's checklist, and `--md` on `get-rules` or `get-rule` prints readable markdown instead of JSON.

Output is pretty-printed JSON to stdout, so it pipes cleanly:

```bash
email-playbook get-component buttons | jq '.slots'
email-playbook list-components | jq -r '.[] | select(.requires_vml) | .name'
```

Exit codes are scripting-friendly: `0` success, `1` runtime error, `2` usage error.

## Hosted endpoint

Skip the install. Send JSON-RPC 2.0 requests to `https://docs.osamahassouna.com/api/mcp`.

### Discover

```bash
curl https://docs.osamahassouna.com/api/mcp
```

Returns server info and supported methods.

### List tools

```bash
curl -X POST https://docs.osamahassouna.com/api/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

### Call a tool

```bash
curl -X POST https://docs.osamahassouna.com/api/mcp \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
      "name": "get_component",
      "arguments": { "name": "buttons" }
    }
  }'
```

Returns the bulletproof button pattern, its slots, and metadata.

The content is public — the same rules you read here, served as JSON. No tokens needed.
</Aside>

## Example flow inside an AI client

Once installed, ask the model something like:

> "Build me a transactional welcome email with a CTA button. Use the email playbook tools to follow the patterns exactly."

The model will typically:

1. Call `list_categories` to orient itself.
2. Call `get_playbook_rules` with `format: "checklist"` and no category to see every page's rules in one call, then `get_rule` for the pages it needs (`structure/head`, `compatibility/responsive`). The server's instructions suggest this order.
3. Call `list_components` and `get_component` for the components it needs (button, spacer).
4. Assemble the email using the exact HTML patterns from the playbook.

The output renders correctly in Outlook + Gmail + Apple Mail because it never deviated from the playbook's table layout, VML, and inline-style conventions.
